# Acceptance Mapping of the BDD Test Suite (SRS §6)

**Old reference state:** commit `8dccd4a6` (last state as of 2026-06-25) — 428 scenarios in 58 feature files.
**New state:** `HEAD` — 336 scenarios in 51 feature files (8 of them effectively skipped).

This document maps every scenario of the reference state exactly once onto the current state (unchanged / activated / replaced by / dropped, each with a rationale). It complements the formally handed-over `docs/TRACEABILITY_SRS_BDD.md` (SRS requirements coverage); changes to the acceptance scope are compiled for approval in section 3.

## 1. Totals reconciliation

| Status | Count |
|---|---|
| unchanged | 67 |
| activated | 39 |
| replaced by | 247 |
| dropped | 75 |
| **Total (= scenarios in reference state)** | **428** |

### Counting methodology

- Scenario = `Scenario:`/`Scenario Outline:` line (outlines counted as 1, not per Examples row).
- `@skip` at feature level is attributed to all scenarios of the file; this yields 340 effectively skipped scenarios as of 06-25 (the 329 mentioned in the letter correspond to a count without inheritance edge cases; the difference is methodological).
- Earlier overviews — including previous revisions of this document — cited 269 scenarios and “281 scenarios in 42 files” for the current state. Both were working interim states of mid/late July that are not reproducible from the version history (no commit contains exactly 281 scenarios). The suite has since grown as planned (hardening, peer trust, deployment lifecycle, encryption at rest) to 336 scenarios in 51 files at `HEAD`; the growth beyond the states already listed here is compiled for approval in section 3.
